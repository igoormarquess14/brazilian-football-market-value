# Divergences between the thesis/Gretl and the repository

Per `CLAUDE.md`: the thesis is the source of truth and no result in it is "corrected" in this repository. Every divergence found between what was published and what exists today in the code/data is documented here, even after it is resolved.

## 1. Corrupted data in `dados/df_mc.csv` (RESOLVED on 2026-08-31)

**What was expected:** `dados/df_mc.csv` should be byte-for-byte compatible with the base Gretl used in the 2025-10-16 session (`session.inp`) to produce Table 7 and Appendix A.

**What was found:** the file had a modification date of 2025-11-18 — one month after the Gretl session. The `fb_xG+/-` cell for the player Jádson (Juventude) contained the literal value `"x "` instead of a number. Running OLS with that row removed (N=86) or with the value replaced by 0 (N=87) did not reproduce the Table 7 coefficients within the tolerance defined in `CLAUDE.md`.

**Root cause:** the file was overwritten by some later pipeline step (likely a new export/merge run after the final estimation), introducing the corruption. There is no indication the thesis used the value `"x "` — Appendix A explicitly shows the model's VIF and F statistic with N=87 and coefficients that only reproduce with a real numeric value in that cell.

**How it was resolved:** the correct value, `-17.1`, was located in three independent, agreeing sources, all predating the corruption: `dados/df_final.csv` (same date as the Gretl session, 2025-10-16), `legacy/modelagem_exploratoria/final_mc.csv` (intermediate file from 2025-10-02), and `dados/df_final.tex` (at the time; now regenerated as `outputs/df_final.tex` by `codes/pipeline/14_csv_to_latex.py`). The cell was corrected surgically (no other data in the file was altered). With the fix, `codes/pipeline/13_estimate_mc_baseline_model.py` reproduces every value in Table 7/Appendix A within the tolerance set by `CLAUDE.md` (see `outputs/mc_baseline_model.txt`).

## 2. Absence of complete Gretl artifacts (open)

**What was expected:** a Gretl session file (a `.gdt` with the loaded base, or a `.gretl` with the full saved session) for a row-by-row check against the original software.

**What exists:** only `session.inp`, a command log auto-generated by Gretl (not a ready-to-run script — the file itself notes "this log will probably need to be edited to be used as a script"). It was enough to confirm the model's exact specification (`ols ln_Value_Num 0 age_centered age_sq fb_xG fb_MnMP`, without `--robust`) and the estimation date, but it does not allow comparing predictions/residuals observation by observation directly in Gretl.

**Impact:** none on the reproduced result — the comparison was made against the numbers printed in Appendix A of the thesis, which include the full regression output, the residual correlation matrix, VIF, and the BKW collinearity diagnostic. Documented here purely for transparency about the source's limitation.

## 3. Broader specifications in the Python code than what was published (open)

**What was published:** a single model, restricted to midfielders (N=87), with 4 explanatory variables (`age_centered`, `age_sq`, `fb_xG+/-`, `fb_Mn/MP`), with no position dummies.

**What exists in `legacy/`:** scripts such as `modelagem_exploratoria/ols_por_posicao.py`, `modelagem_exploratoria/ols_rnc_pipeline.py`, and `clustering/cluster_pipeline_v2*.py` estimate additional models not published in the thesis — by position (ATA/DEF/GK), with extra variables (`Height`, `fb_PPM`, `pts_rnc`) and using club-clustered robust standard errors (HC1), plus a hierarchical clustering step and a merge with the RNC club ranking.

**Nature of the divergence:** not an error — it is exploratory work that did not make it into the final defended version. See `PLAN.md`, Step 7, for the decision on keeping this material as clearly labeled "extensions" or excluding it from the public repository. In this session (Step 4), this material was isolated into `legacy/clustering/` and `legacy/modelagem_exploratoria/`.

## 4. Two links in the cleaning chain with no surviving script (open, no impact on the result)

While reconstructing the full pipeline in Step 4 (see `docs/pipeline.md`), two steps between the raw base and the final base have no surviving script in the repository:

1. **Column selection**: `dados/clubes/outcome/final_merged_fixed.csv` (51 columns) was reduced to `final_merged_filtrado.csv` (15 columns). The script that should have done this, `criar_csv_filtrado.py`, exists but is empty (0 bytes). The transformation itself is simple and was confirmed by comparing the two outputs — but the original code was never saved.
2. **Creation of the position dummies**: `final_merged_filtrado.csv` gained the columns `Dum_GK/DEF/MC/ATA` at some point, with no script in the repository performing that assignment. Worse: the mapping `Position_Num → Dum_*` **is not a pure function** — the same `Position_Num` (e.g., `5`) appears associated with `Dum_DEF` in some rows and `Dum_MC` in others. This indicates manual reclassification of specific cases (versatile players, likely position-capture errors in the scraping), not a recoverable automatic rule.

**Impact:** none on the published model. The files resulting from both steps are preserved and committed, and serve as a verified checkpoint for the rest of the chain (see `docs/pipeline.md`, Segment 2). Documented here instead of simulated with an invented rule, per `CLAUDE.md`.
